CANVOTES — Master Product & Engineering Specification

You are a senior Android engineer, product designer, and software architect. Your task is to design, architect, build, test, and deliver a polished native Android application named Canvotes.

Do not treat this as a basic note-taking application. Canvotes is an infinite-canvas workspace designed for people who want to think, write, sketch, annotate, and organize ideas naturally.

The final application must be genuinely usable, visually polished, performant, and architecturally maintainable.

---

1. Product Vision

Product: Canvotes
Platform: Android only
Primary language: Kotlin
UI framework: Jetpack Compose

Canvotes combines:

- Infinite digital canvas.
- Stylus-first handwriting.
- Traditional textbox-based note-taking.
- Image and shape placement.
- PDF import and annotation.
- Notebook and page organization.

The experience should feel like a premium, modern productivity application.

Core philosophy:

"An infinite space for finite distractions."

The interface must stay minimal and allow users to focus on their ideas rather than application controls.

2. Visual Design System

Overall aesthetic

Use a strictly monochromatic visual identity.

Primary colors:

- Black
- White
- Neutral grays

Avoid unnecessary accent colors, colorful gradients, excessive shadows, colorful illustrations, and visually noisy components.

The design should feel modern, editorial, clean, and premium.

Use generous whitespace, carefully balanced spacing, subtle borders, rounded corners, and restrained animations.

Light theme

- White or near-white application background.
- Black primary text and icons.
- Neutral gray secondary text.
- Subtle gray borders and dividers.
- White canvas surface.

Dark theme

- Deep black or near-black application background.
- White primary text and icons.
- Neutral gray secondary text.
- Subtle dark-gray borders.
- Dark canvas surface.
- Polka dots should remain visible without becoming distracting.

Support:

- Light mode.
- Dark mode.
- Follow system appearance.

Persist the selected theme.

Canvas background

The canvas must have a distinctive, subtle polka-dot background.

Requirements:

- Precisely spaced circular dots.
- Consistent dot spacing.
- Low-contrast appearance.
- Dots remain visually consistent while zooming and panning.
- Background must be rendered efficiently.
- Support different zoom levels without visual artifacts.

The dots must adapt to light and dark themes.

Do not use a static background image. Implement the pattern through efficient custom drawing.

3. Application Architecture

Use modern native Android development practices.

Required stack:

Layer| Technology
Language| Kotlin
UI| Jetpack Compose
Design system| Material 3
Architecture| Clean Architecture + MVVM
Dependency injection| Hilt or Koin
Database| Room
Preferences| DataStore
Navigation| Type-safe Compose Navigation
Async operations| Kotlin Coroutines + Flow
Image loading| Coil
PDF support| Android PdfRenderer or a suitable maintained library
Testing| JUnit, Compose UI Testing

Use current stable compatible library versions at implementation time.

Do not introduce unnecessary dependencies.

Organize the project into logical modules or clearly separated packages:

- app
- core
- design
- data
- domain
- feature-home
- feature-notebooks
- feature-canvas
- feature-settings

Keep the canvas rendering and interaction engine independent of the presentation layer.

4. Application Structure

The application should have the following primary areas.

A. Home Screen

The home screen is the user's workspace.

Include:

- Canvotes branding.
- Search.
- Notebook collection.
- Recently opened notebooks.
- Create notebook action.
- Settings access.
- Empty state for new users.

Notebook cards should be minimal, monochromatic, and visually consistent.

Each notebook should have:

- Name.
- Optional description.
- Creation date.
- Last modified date.
- Page count.

Allow users to:

- Create notebooks.
- Rename notebooks.
- Delete notebooks with confirmation.
- Open notebooks.
- Search notebooks.

B. Notebook Screen

Each notebook contains multiple pages.

Include:

- Notebook title.
- Page list or page grid.
- Create new page action.
- Rename page.
- Duplicate page.
- Delete page.
- Reorder pages.

Make navigation between pages straightforward.

C. Canvas Editor

This is the most important part of Canvotes.

The editor should occupy almost the entire screen.

Avoid unnecessary panels and permanently visible toolbars.

Provide:

- Infinite canvas.
- Polka-dot background.
- Smooth pan and zoom.
- Floating or compact contextual toolbar.
- Undo and redo.
- Save status.
- Page navigation.
- Canvas settings.

Prioritize the canvas itself.

5. Infinite Canvas Engine

Implement a custom canvas engine using Jetpack Compose Canvas and appropriate Android pointer input APIs.

The canvas must support:

- Infinite-feeling workspace.
- Two-finger pan.
- Pinch-to-zoom.
- Stylus drawing.
- Touch interaction.
- Object selection.
- Object movement.
- Object resizing.
- Canvas coordinate transformations.

Use a consistent world-coordinate system.

The application must correctly convert between:

- Screen coordinates.
- Canvas coordinates.
- Zoom scale.
- Canvas translation.

Drawing data must be stored in canvas/world coordinates, not screen coordinates.

Implement spatially efficient rendering and avoid unnecessary recomposition.

The canvas should remain responsive when it contains substantial amounts of content.

Avoid rebuilding and redrawing the entire document unnecessarily.

6. Stylus & Handwriting Engine

Stylus interaction is a core product feature.

Implement a dedicated input system.

Required capabilities:

- Pen tool.
- Pencil tool.
- Highlighter.
- Eraser.
- Adjustable stroke width.
- Adjustable opacity.
- Pressure sensitivity when supported by hardware.
- Palm rejection.
- Smooth stroke rendering.
- Stroke selection.
- Stroke movement.
- Stroke deletion.

Use Android MotionEvent information where appropriate to distinguish stylus input from finger input.

Support stylus pressure and tool type.

Use appropriate input prediction or smoothing techniques where beneficial.

Prioritize low input latency.

Important interaction rules

- Stylus input should draw.
- Finger input should pan the canvas by default.
- Two fingers should pan and zoom.
- Do not accidentally create strokes from palm or ordinary finger contact.
- Provide an appropriate touch-only fallback for devices without stylus support.

Do not falsely claim hardware-level palm rejection if the device or operating system does not provide it. Implement the best available application-level input filtering.

7. Textbox System

Users must be able to create traditional text elements directly on the canvas.

Features:

- Add textbox.
- Edit text.
- Move textbox.
- Resize textbox.
- Delete textbox.
- Text alignment.
- Font size.
- Bold.
- Italic.
- Text color in monochrome.
- Basic formatting.

Textboxes should behave like independent canvas objects.

When editing a textbox, provide a comfortable text editing experience with the Android keyboard.

Preserve textbox positions and formatting when saving.

8. Shapes & Image Support

Support the following shapes:

- Rectangle.
- Rounded rectangle.
- Circle.
- Ellipse.
- Straight line.
- Arrow.
- Freeform drawing.

Allow users to:

- Insert shapes.
- Resize shapes.
- Move shapes.
- Delete shapes.
- Adjust stroke thickness.
- Change monochromatic stroke and fill settings.

Image support:

- Import images using Android Photo Picker or Storage Access Framework.
- Display images on the canvas.
- Move, resize, and delete images.
- Preserve image aspect ratio.
- Persist image references correctly.

9. PDF Import & Annotation

Users must be able to import PDFs into Canvotes.

Implement:

- PDF selection through Android document picker.
- PDF rendering.
- Page navigation.
- Zoom.
- Handwriting over PDF pages.
- Text annotations.
- Shapes over PDF pages.
- Saving annotation data.
- Reopening annotated documents.

Keep the imported PDF content and user annotations logically separate.

Do not rasterize the entire PDF into a single image as the primary storage strategy.

Use an appropriate rendering and annotation architecture.

10. Object Selection & Editing

Implement a selection system that works across different canvas objects.

Users should be able to:

- Select individual objects.
- Select multiple objects where practical.
- Move selected objects.
- Delete selected objects.
- Duplicate objects.
- Resize objects.
- Use a lasso selection tool for handwriting and objects.

Provide clear but subtle selection indicators.

11. Undo & Redo

Implement a reliable command/history system.

Undo and redo should support:

- Drawing strokes.
- Erasing.
- Text creation and editing.
- Shape creation and modification.
- Image placement.
- Object movement.
- Object deletion.

Avoid implementing undo/redo as a superficial UI feature. It must correctly restore document state.

12. Local-First Storage

All user-created content must persist locally.

Use Room for structured metadata and document state.

Design a versioned document format that can represent:

- Canvas viewport.
- Strokes.
- Textboxes.
- Shapes.
- Images.
- PDF references.
- Object properties.
- Document metadata.

Use efficient serialization and avoid storing large binary image or PDF data directly inside Room rows.

Store binary assets in managed application storage.

Requirements:

- Automatic saving.
- Save after meaningful changes.
- Avoid excessive disk writes.
- Recover from application termination.
- Restore the last opened notebook and page.
- Handle interrupted writes safely.
- Support document migration.

Cloud synchronization is NOT part of the initial release.

However, the storage architecture must leave room for future synchronization without requiring a complete rewrite.

13. Application Settings

Provide a minimal settings screen containing:

- Appearance: Light / Dark / System.
- Default canvas tool.
- Default pen thickness.
- Default canvas background.
- Stylus behavior.
- About Canvotes.
- Application version.

Keep settings simple.

14. UI & Interaction Quality

Use modern Jetpack Compose patterns.

Use:

- Material 3 components where appropriate.
- Custom components for Canvotes-specific interactions.
- Smooth and restrained transitions.
- Subtle interaction feedback.
- Proper typography hierarchy.
- Consistent spacing.
- Appropriate accessibility descriptions.
- Responsive layouts for phones and larger Android screens.

Do not blindly use default Material 3 styling everywhere.

Customize the component system to match the monochromatic product identity.

Avoid:

- Excessive dialogs.
- Cluttered toolbars.
- Unnecessary bottom navigation.
- Oversized controls.
- Random animations.
- Decorative elements that compete with the canvas.

15. Performance Requirements

Performance is critical, especially for handwriting.

Prioritize:

- Low-latency input.
- Efficient stroke rendering.
- Efficient viewport culling.
- Avoiding unnecessary recompositions.
- Smooth zooming and panning.
- Efficient document serialization.
- Background persistence.
- Memory-efficient image and PDF handling.

Test the application with:

- Hundreds of strokes.
- Large canvas documents.
- Multiple images.
- Multiple PDF pages.
- Repeated zoom and pan operations.

Do not sacrifice input responsiveness for architectural complexity.

16. Security & Privacy

Canvotes is local-first.

- Do not upload user notes.
- Do not add analytics that collect document contents.
- Avoid unnecessary permissions.
- Use Android's document and photo pickers.
- Protect against corrupted document data.
- Handle storage failures gracefully.

19. Working Instructions

Before implementation:

1. Inspect the existing repository.
2. Identify the available Android SDK, Gradle, Kotlin and emulator environment.
3. Determine the actual project state.
4. Identify technical risks.
5. Create a detailed implementation plan.
6. Select compatible, maintained libraries.

Then begin implementation.

Do not stop after producing a plan.

Do not ask unnecessary questions when a sensible engineering decision can be made.

Do not create fake buttons, placeholder interactions, or non-functional screens.

Do not claim that features are implemented unless they have been verified.

If a feature cannot be fully implemented because of hardware or environment limitations, document the limitation and implement the best reliable fallback.

Preserve working code when introducing new features.

Use clean commits or clearly documented milestones if Git is available.

20. Definition of Done

Canvotes is ready for its first release when:

- A user can create notebooks and pages.
- The infinite canvas works smoothly.
- The polka-dot background works in both themes.
- Stylus handwriting works.
- Finger-based navigation works.
- Textboxes work.
- Shapes work.
- Images can be imported and manipulated.
- PDFs can be imported and annotated.
- Undo and redo work correctly.
- Documents automatically save.
- Documents survive application restarts.
- Light, dark and system themes work.
- The application builds successfully.
- Critical functionality has been tested on an actual Android runtime.

The final result should feel like a cohesive, premium note-taking product rather than a collection of unrelated features.

Your priority order:

1. Excellent canvas experience.
2. Excellent stylus experience.
3. Minimal and beautiful interface.
4. Reliable persistence.
5. Complete note-taking functionality.
6. Maintainable architecture.

Build Canvotes as a real product, not a prototype.
